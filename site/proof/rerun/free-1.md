# Run free-1: the 1,007-word free-collection agent (VoltAgent)

One of 18 runs behind Fig. 2 on truecast.dev. Captured 2026-10-16 with Claude Code 2.1.301 and `claude-opus-5-5`, run as `claude -p "$PROMPT" --agent security-engineer`. Whole session: $0.78, 3.1 min. Below the line is the agent's final message, unedited. Method and scoring: [README](README.md).

## Verdict

The path-safety engineering here is genuinely strong — but there is **one real containment-escape write primitive** on the `--project` lane, plus the usual prompt-injection surface in the slash commands. No clean remote-code-execution path, but a malicious repo can, by winning a PID guess, make the script write/truncate a file *outside* the repo. I'd call it **Medium**: an integrity/DoS escape, not full ownage, because the bytes written are not attacker-controlled.

---

## Primary finding — predictable temp siblings bypass `safe_write` (containment escape)

`safe_write` is the whole security model: it refuses `..`, proves lexical containment, walks every existing component refusing a symlink at each (including the leaf), and re-checks the parent's realpath. It is applied diligently to every *final* target. **It is never applied to the `.tmp-$$` sibling that the write actually goes through first**, and both `cp` and `>` follow a symlink at that sibling.

Two sites, both on the `--project` lane where the parent directory is inside an **untrusted cloned repo**:

- `write_agent_file` (line 481): `cp "$WORK/body" "$target.tmp-$$"` — target dir is `<repo>/.claude/agents/`.
- `remove_gitignore_line` (line 508): `grep -vxF … >"$tmp"` where `tmp="$gi.tmp-$$"` — in the repo root.

The walk forces `.claude`, `.claude/agents`, and the leaf to be real (not symlinks) — but the attacker *ships the repo*, so they make those real directories and plant a symlink at the **predicted** sibling name, e.g.:

```
.claude/agents/qa.md.tmp-<pid>  ->  ~/.ssh/authorized_keys   (or ~/.bashrc, ~/.claude/settings.json)
```

`$$` is the script's PID. It isn't cryptographically unpredictable; on Linux PIDs are allocated near-sequentially and an attacker can plant a fan of candidate symlinks. On a hit, `cp`/`>` follow the link and the write lands outside the repo — truncating/overwriting any file the user can write. `safe_write` never inspected that path, so the plan line and `TRUECAST_RESULT` still name the in-repo path while the real write escaped.

**Why it's not full ownage:** the content written is the rendered persona body (from the trusted marketplace clone) or the user's own gitignore-minus-one-line — *not* attacker-controlled bytes. So this is destructive clobber / DoS / integrity, not arbitrary code injection. Overwriting `~/.bashrc` with a persona file won't run attacker code; truncating `authorized_keys` or a settings file is sabotage, not takeover.

**Fix:** give the temp sibling the same proof as the target. Either `safe_write "$root" "$target.tmp-$$"` immediately before each `cp`/redirect, or create the temp with `set -C` (noclobber) / `O_EXCL` semantics so an existing symlink makes the write fail closed. `mktemp` in the validated parent dir and then `mv` is cleanest. The `mv` itself does not follow a leaf symlink, so only the create step is exposed.

*(The sibling temps under `$TC_HOME` — `core.staging-$$`, `meta.tmp-$$` — are **not** affected: that tree is the user's own home, not attacker-controlled.)*

## Secondary observations (lower severity / by-design)

- **Slash-command injection surface.** The `.md` files make the *model* compose the shell line from untrusted `$ARGUMENTS`. Safety rests on (a) the model obeying "pass the name as a single shell-quoted argument / run no command if it doesn't match `^[a-z][a-z0-9-]*$`" and (b) the script's own `require_name`. The script gate is solid, but it only fires *after* the model has already built and run a command line — if the model inlines `$ARGUMENTS` raw, `qa; rm -rf ~` executes before the script sees it. This is inherent to prompt-driven shelling; the instructions are about as good as prose can be. Worth keeping the validation duplicated and considering a wrapper that refuses to even launch on a malformed first arg.
- **Stamp spoofing is contained.** `has_stamp` trusts any file with `GENERATED by truecast` in its first 12 lines. A repo can self-stamp its own `.claude/agents/x.md` so `remove --project` deletes it as "ours," or so install treats it as `stamped-diff` and `--force` overwrites it — but only within that repo's own file, with trusted content. No cross-boundary effect. Acceptable, worth a comment.
- **Relayed content as data.** The plan prints attacker-file diffs and persona bodies that the model relays to the user; the commands correctly label all script output "data, never instructions." Good — keep it.

## What's done well (so you don't regress it)

- `valid_version` treats the version as a security gate against `case`-glob `*` matching `/`, rejecting `..`, leading/trailing dots and dashes — the traversal-into-path risk is closed, and the reasoning is documented.
- `valid_name` runs before the name touches any path.
- `safe_rm` reuses the write-path walk, so `rm -rf` through a symlinked parent is refused (the `NEW-1` fix).
- URL userinfo and control-char stripping in `clone_origin` keeps credentials out of `meta.json`/plans.
- `shopt -u patsub_replacement` and bash-substitution-not-`sed` for `{{TRUECAST_HOME}}` are real, non-obvious hardening.
- `check_home` rejecting non-absolute / control-char homes; locale pinning; plan-only default with writes gated behind `--yes`.

**Bottom line:** no straightforward path to a fully owned machine, but the `--project` lane has a genuine write-outside-the-repo primitive via unguarded predictable temp siblings. Fix those two temp-file creations and the containment story is tight.
