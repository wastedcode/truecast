# Write the brand guidelines — short enough to be used

Most brand books are opened once. Write the one people (and agents) consult before every new surface.

## Contents (one page where possible; a `BRAND.md` beside the tokens)
1. **The idea** in a sentence, and the personality traits ("…not …").
2. **Why** — the two or three reasons behind the big choices, so extensions stay true.
3. **Tokens** — link the CSS/JSON file; show the colour roles and the type scale as rendered samples.
4. **The mark** — versions, clear space, minimum size, and 4–6 visual don'ts (stretched, recoloured, on
   low contrast, with effects).
5. **The device** — how and where to use it; one right, one wrong example.
6. **Imagery** — allowed and forbidden, with examples.
7. **Voice** — the attributes with one rewritten example each; words we own / never use.
8. **Assets** — where every file lives and what it's for.

## The discipline
Examples over adjectives. Keep it in the repo, versioned with the tokens. If a rule can be a token or a
lint check, make it one.
