It found a real hole in our own installer. Then we tested it fairly.

Fig. 1’s review showed that a hostile repo could get its text written into your ~/.bashrc. We fixed it. Then we asked whether a 76-word agent would have caught it too: the same prompt, byte for byte, given straight to three security-engineer agents, six runs each. It did, in all six runs.

So at catching these, a short prompt held its own. No run of any agent found all three holes, and ours found as many as the 76-word one, at $1.04 a run against $0.85. What changed was the hand-off: every truecast run closed on a GO or NO-GO and ranked its findings P1–P3, by when to fix them, as its agent file asks. None of the other twelve runs did.

That’s one review, of one kind. The case for truecast is the rest of this page: twelve roles already written, a brief each keeps for your repo, and updates that never touch it. Every run is published, so you can check this one.

A teammate is a playbook, your brief, and its own context window.

The playbook.

17 skills, 3 reference notes and its agent file for security-engineer: 12,697 words of plain Markdown (Fig. 3). It can open any of them mid-task; in Fig. 1 it opened two. These load only into that teammate; they aren’t Claude Code Skills and don’t crowd your main session.

Your brief.

One file in your repo, .truecast/agents/security-engineer/instance/mandate.md: what the project is, what matters, where the bar is. It reads it first. Updates never touch it. No brief? It works from what you ask. Start one: step 4 ↓

Its own context window.

Each teammate is a native Claude Code subagent. It reads and tests in its own context and hands your session back the 2,780-token report. The 66k tokens of digging stay in its own context.

Two commands. Then call it by name.

  1. 1 In your terminal

    claude plugin install truecast \--marketplace wastedcode/truecast

    Needs Claude Code 2.1.292 or later; check with claude --version. That’s the installer. You run it once per machine.

  2. 2 In Claude Code, in any project

    /truecast:install security-engineer

    Was Claude Code already open when you ran step 1? Run /reload-plugins first. Then you’ll see its plan before anything is written. Say yes and it’s ready.

    Want a different one? Swap the name, or copy it from the twelve below ↓

  3. 3 Call it by name

    @agent-security-engineer review the changes on this branch before I merge

    An example prompt: any teammate, any request. Or type @ and pick it from the list. Either way, that teammate takes the job.

  4. 4 Give it your brief optional

    curl -fsSL --create-dirs \-o .truecast/agents/security-engineer/instance/mandate.md \https://raw.githubusercontent.com/wastedcode/truecast/main/personas/security-engineer/instance-template/mandate.md

    In your repo, in a terminal (macOS, Linux or WSL). It saves the template: the project and its trust model, your job here, how you work. Fill it in; the teammate reads it first. Another teammate? Swap security-engineer for its name in both places.

Later

Take the improvements, or take it back out

Take the improvements

In your terminal, then restart Claude Code:

claude plugin marketplace update truecast
claude plugin update truecast@truecast

The first fetches new versions of every teammate. The second updates the installer itself.

Then, in Claude Code:

/truecast:update security-engineer

It shows the new version’s plan first. Your brief is never touched.

Take it back out

In Claude Code:

/truecast:remove security-engineer

Same deal: it lists what it will delete and waits for your yes. /truecast:list shows what you have.

To remove the installer too, in your terminal:

claude plugin uninstall truecast@truecast

Questions

I already wrote an agent file. Why switch?

If it does the job, keep it: in our fair test a 76-word agent caught as much as ours. truecast won’t overwrite it, and won’t install over it. What it adds is the rest: twelve roles already written, a brief each keeps for your repo, versioned updates that never touch that brief, and a plan before anything is written. To run ours beside yours, rename your file first, or install ours as a plugin with /plugin install security-engineer --marketplace wastedcode/truecast (Claude Code 2.1.275 or later) and call it as security-engineer:security-engineer.

What about the big free agent collections?

We tested one: the 1,007-word security-engineer from VoltAgent’s collection, given the same prompt six times. It caught 6 of the 18 holes we scored, against 9 for ours and 9 for a 76-word agent, and it was the cheapest at $0.68 a run. Fig. 2 has every run, and the 18 reports are unedited. It’s one review, so read it as one test, not a benchmark.

What does it cost?

Nothing to install. Each teammate runs on Opus, on your own Claude Code usage (subscription or API key). In the fair test a truecast review averaged $1.04 for the whole session at API prices, against $0.85 with a 76-word agent and $0.68 with the free-collection one.

Does it learn my project?

Not on its own yet. It reads your brief every time. A learning loop that proposes brief updates for you to approve is planned, not shipped.

Can my whole team get it?

Yes. Merge these two keys into the repo’s .claude/settings.json, and Claude Code offers the teammate to anyone who trusts the folder:

{
  "extraKnownMarketplaces": {
    "truecast": {
      "source": { "source": "github", "repo": "wastedcode/truecast" }
    }
  },
  "enabledPlugins": { "product-manager@truecast": true }
}

Installed this way it answers to product-manager:product-manager, and updates come with the marketplace, without the plan step. Commit it only for a marketplace you trust.

Can I write my own?

Yes. A teammate is a folder of Markdown and one persona.toml. Authoring guide → Open a PR to add it to the catalog.
